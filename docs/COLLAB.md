# 협업 방식

## 하루입니다

예선은 10일이었습니다. 거기서 나온 것 중 상당수는 오늘 안에 안 됩니다.

| 예선에서 만든 것 | 든 시간 |
|---|---|
| 리플레이 시각화 도구 | 그 자체로 하루짜리 |
| GA 파라미터 탐색 | 25세대, 수렴까지 며칠 |
| 공식 사이트 로그·제출본 크롤러 | 라운드가 여러 번 돌아야 값을 함 |
| 라운드별 통계 리포트 | 위와 같음 |

만들지 말라는 게 아니라, **시작하기 전에 "오늘 안에 값을 하나"를 한 번 물어보라는**
뜻입니다. 예선엔 값을 했습니다. 오늘은 조건이 다릅니다.

## 어디서 일하나

| | 경로 | 규칙 |
|---|---|---|
| 개인 | `~` (각자 홈) | 마음대로. 팀원이 **읽을 수는** 있고 쓰지는 못합니다 |
| 공유 | `/srv/nypc` (= `~/shared`) | 전원 읽기/쓰기 |

보여줄 게 있으면 홈 경로를 알려주면 됩니다 — 복사할 필요 없습니다.
팀이 함께 쓰기 시작한 것만 공유 폴더로 옮기세요.

**남의 파일은 고칠 수는 있어도 `chmod`는 못 합니다.** 소유자만 됩니다.
그래서 실행 권한이 필요한 파일(`run.sh` 등)은 **만든 사람이** `chmod +x` 해야 합니다.
막히면 소유자에게 부탁하세요.

### 정확히 뭐가 되고 뭐가 안 되나 (실측)

| | 내 홈 | 남의 홈 | 공유 폴더 |
|---|---|---|---|
| 읽기 | O | **O** (기본 모드 파일) | O |
| 쓰기·수정 | O | **X** | O |
| 파일 생성·삭제 | O | **X** | O |
| `chmod` | O | X | 내가 만든 것만 |

남의 홈은 **읽기 전용**입니다. 그래서 "내 변형 좀 봐줘"는 경로만 알려주면 되고,
복사할 필요가 없습니다. 대신 남의 작업을 실수로 망가뜨릴 수도 없습니다.

가리고 싶은 파일은 `chmod 600 <파일>` 하면 팀원도 못 봅니다.
기본 umask가 `0002`라 그렇게 하지 않으면 새로 만드는 것은 팀원에게 보입니다.

`sudo`는 아무에게도 없습니다. 시스템 변경은 통합자를 거칩니다.

## git

**신경 쓰지 마세요.** 2분마다 자동 스냅샷이 돕니다. 브랜치도 푸시도 없습니다.
git은 협업 수단이 아니라 **되돌리기 수단**입니다. 쓸 일은 뭔가 잘못됐을 때뿐입니다
(되돌리는 법은 [../CLAUDE.md](../CLAUDE.md)).

이력은 작업 트리 밖(`/srv/nypc-git`)에 있어서, 공유 폴더 안에서 무슨 일이 나도 살아남습니다.

## 측정에서 조용히 틀리는 것

티가 안 나서 위험합니다. 셋 다 실제로 겪은 것입니다.

**소표본은 거짓말을 합니다.** 20판 12승(60%)은 표준오차가 ±11%p라 실력 차이의
근거가 못 됩니다. 한 판이 **0.36초**(파이썬 샘플 양쪽, 400턴 완주)라 100판·1000판을
잡는 비용이 분 단위입니다. **적게 돌릴 이유가 없습니다.** 예선에서도 노이즈가 큰
구간은 1000판을 돌려야 순위가 안정됐습니다([REFERENCE.md](REFERENCE.md)).

집계·표준오차·결과 적재는 `tools/match.sh` 가 합니다. 직접 만들지 마세요.
같은 조건에서 양쪽 진영을 번갈아 두는 것(페어드)도 이미 합니다 — 적은 판수로
같은 확신을 얻습니다.

**CPU를 서로 뺏으면 승률이 실력이 아니라 서버 부하를 잽니다.** 16코어를 4명이
씁니다. 턴 100ms 제한이 있는 대국에서 코어가 모자라면 가짜 타임아웃이 납니다.
병렬은 `match.sh -j N` 으로 돌리세요 — `corepool.sh` 로 코어를 먼저 확보합니다.
직접 `&` 로 띄우지 마세요.

**채점기는 코어를 하나만 줍니다.** 16코어는 개발용이지 채점 환경이 아닙니다.
시간을 재려면 한 코어에 묶으세요:

```bash
tools/corepool.sh 1 -- taskset -c 0 ./main NYPC
```

자세한 건 [../CLAUDE.md](../CLAUDE.md) 의 "The judge gives your program ONE core".
