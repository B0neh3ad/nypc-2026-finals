## 이 폴더의 위치: 어디까지나 **참고용**

**팀 방침(2026-08-29, jinsu): 예선 자산은 참고용이다. 애매하면 반드시
from scratch로 새로 쓴다.**

아래에 "본선은 예선과 같은 게임"이라는 실측 결과가 나옵니다. 그건 **규칙을
이해하고 예선 판단의 맥락을 읽는 데** 쓰라는 사실이지, 예선 코드를 포크해서
고쳐 쓰라는 뜻이 아닙니다. 이유는 셋입니다.

- 예선 봇은 **완전정보 게임**을 전제로 진화한 코드입니다. 본선은 전장의 안개가
  있습니다. 상대 정보를 쓰는 지점이 1만 줄 안에 흩어져 있고, 그걸 다 찾아냈다고
  확신하기 어렵습니다. **틀린 곳을 못 찾은 채로 튜닝하면 서버 부하를 재는 것과
  같은 종류의 조용한 실패가 납니다.**
- 상수가 크게 바뀌어서(아래 표) 예선 전략의 균형점이 지금 균형점이 아닙니다.
  코드는 남아도 그 코드가 구현한 **판단**은 무효입니다.
- 대회 중에 남의 1만 줄을 읽고 검증할 시간이 없습니다. 우리가 짠 500줄이
  물려받은 10,000줄보다 빠르게 고쳐집니다.

**읽으세요. 베끼지 마세요.** 특정 부분을 가져다 쓰는 게 명백히 이득이라고
판단되면 그때 팀에 한마디 하고 가져오세요.

## 본선은 예선과 같은 게임입니다 (실측)

본선 심판기와 예선 심판기를 diff한 결과:

```
reference/engine/nation-providing/testing-tool.py   1599줄   (예선)
problem/nation-fr-providing/testing-tool.py        1641줄   (본선)
                                    유사도 96.2%, 바뀐 줄 124개
```

CLI 인자(`-c -i -l -s -a -b --seed --NP --KP`)는 한 글자도 다르지 않고,
config.ini 키·로그 포맷·와이어 프로토콜도 같습니다.

이 문서는 예전에 "본선 문제가 다르면 예선 봇 코드는 쓸모없다"고 적고 있었습니다.
그 전제는 틀렸지만, **쓸모가 있다는 것과 가져다 쓰라는 것은 다른 말입니다** —
위 방침을 보세요.

### 바뀐 것 1 — 상수 재조정 (규칙 구조는 그대로)

| | 예선 | 본선 |
|---|---|---|
| 시작 금화 | 500 | **750** |
| 게임 길이 | 200일 | **400일** |
| 맵 크기 `N` | 51 ~ 109 | **181 ~ 249** |
| 본부 업그레이드 (Lv3/4/5) | 1200 / 2400 / 3600 | **1000 / 2000 / 3000** |
| 기지 Lv1/2/3 | 300 / 600 / 1000 | **500 / 550 / 600** |
| 맵 생성 최소 간격 `GEN_D` | 100 | **800** |
| 거점 수 `K` | `0.15N ~ 0.2N` | **`ceil(√N−1) ~ floor(√N+4)`** |

읽는 법: 맵이 2배 이상 커졌는데 거점 수는 비율로 줄었습니다(예선 ~18%, 올해 ~7%).
게임은 2배 길어지고 시작 금화는 늘었습니다. 기지 업그레이드 증분이
500/550/600으로 거의 평평해졌습니다. **예선에서 튜닝한 확장 대 병력 비율은
숫자로든 감각으로든 그대로 가져오면 안 됩니다.**

### 바뀐 것 2 — 전장의 안개 (**올해의 진짜 변경점**)

예선에서는 결과 블록이 **양쪽 이벤트를 병합**해서 왔습니다(`_merge_results`).
상대의 건설·훈련·이동·피해가 전부 보였습니다. **완전정보 게임이었습니다.**

본선에서는 그 병합이 삭제됐고, 대신 이렇게 바뀌었습니다:

- 결과 블록의 이벤트 섹션에는 **내 이벤트만** 옵니다.
- `HOP_VISION = 2` 가 새로 생겼고, `WARRIOR`/`BUILDING` 스냅샷 섹션이 추가됐습니다.
  내 유닛은 전부, 적은 **hop 거리 2 이내**에 있을 때만 보입니다.

정찰·기만·상대 상태 추정이 올해 처음 생긴 축입니다.
**예선 레포에는 이 축에 대한 코드도 경험도 없습니다.**

## 예선에서 비싸게 배운 것 — 이건 그대로 적용됩니다

코드가 아니라 **측정 방법**이라서 게임이 바뀌어도 유효합니다.

- **상대 패널을 고정**했습니다. 과거 챔피언을 상대로 재사용하면 점수가 회차마다
  달라져 비교가 불가능해집니다.
- **winner's curse**: 상위 후보를 뽑은 뒤 새 게임으로 **재평가**해서 순위를 다시
  매겼습니다. 노이즈가 큰 셀은 1000판을 돌려야 믿을 수 있었습니다.

본선은 한 판이 **0.36초**(파이썬 샘플 기준)라 표본을 크게 잡는 비용이 쌉니다.
다만 그만큼 CPU를 쉽게 포화시키니 `tools/corepool.sh` 는 계속 쓰세요.

## 갱신

EC2에는 **GitHub 자격증명을 두지 않았습니다.** 네 명이 함께 쓰는 박스에 토큰이나
배포 키를 올리면 그 GitHub 계정으로 누구든 행동할 수 있게 됩니다.
그래서 여기서는 `git pull`이 되지 않습니다 (읽기는 전부 됩니다).

갱신이 필요하면 통합자가 자기 Mac에서 pull한 뒤 다시 밀어 넣습니다.
